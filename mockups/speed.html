Speed tests

The same level drawn two ways, side by side: the game's canvas drawing as it is now, and the GPU drawing, which composites the map in one WebGL2 pass a frame and draws the hatching from a picture of every stroke made once (no stroke is inked again as the map is explored). Walk to explore a little; the timings below compare the two.

Timings

Milliseconds on this device. A step is seeing from the new square and redrawing the ink; a frame is putting the picture together (for the GPU, waiting for it to finish). The GPU's step leaves out the strokes; its frame does them.

Stroke stamps

The hatching in sight for the whole level, as the map stands now, drawn with the pen (each stroke's outline filled, as the game does) and with stamps (a tapered stroke drawn once at a few thicknesses and bends, then placed stretched and turned where each stroke goes). Close up round the player.

Off the main thread

The same pen hatching inked in a Web Worker on an off-screen canvas: how long it takes in all, and how long the game itself would stand still for it (sending the depth map, and drawing the picture that comes back).

The light's flicker

The lamp flickers every frame, so the map has to be put together every frame even when nothing else changes. How long a frame takes, flickering and not; for the canvas drawing, still means the map as last put together could simply be shown again. On the GPU the flicker is two numbers handed to the one pass.
